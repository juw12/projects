# Brief — Retrieval-Augmented Generation (RAG)

_Produced by Scout (Track B research assistant) · 2026-10-22_

## Summary
RAG is a technique that lets large language models retrieve relevant text from
external sources (databases, documents, web) and fold it into the prompt before
generating an answer. Introduced in a 2020 paper, it grounds output in specific
sources, reduces hallucination, and avoids retraining costs.

## Key points
- RAG = information retrieval + generation: fetch relevant documents, augment the
  prompt, then generate the response.
- Introduced in the 2020 paper "Retrieval-Augmented Generation for
  Knowledge-Intensive NLP Tasks" (Lewis et al., NeurIPS).
- Pipeline: data → embeddings → vector database → retriever selects top-k docs
  per query → LLM generates from query + retrieved context.
- Benefits: fewer hallucinations, no retraining for new/updated data, and
  citable sources for transparency.
- Improvement areas: encoder tuning (dot product, ANN, late interaction/ColBERT,
  SPLADE); retriever-centric methods (ICT pretraining, REPLUG, reranking);
  language-model redesign (RETRO / RETRO++); chunking strategies; hybrid search
  (semantic + full-text).
- Limitations: RAG does **not** eliminate hallucination — models can misinterpret
  correct sources ("RAG poisoning"), blend outdated and updated info, or fail to
  admit uncertainty.
- Applications: grounding model output in authoritative/updated knowledge
  (e.g. healthcare has been studied, with open questions on evaluation).
