How to use Sweep

Sweep turns rough app ideas into checkable plans. Follow the flow: brief → plan → scaffold → sync.

1

Create or unlock your workspace

Choose a workspace name and a strong passphrase. Your data is encrypted at rest in your browser using WebCrypto (PBKDF2 → AES-GCM). No server, no network—everything stays local.

2

Write an idea brief

Describe your app idea: the problem, target user, job-to-be-done, and 2–4 success checks. Be specific—these success criteria become your Definition of Done checklist.

3

Review the generated plan

Sweep analyzes your brief and produces a capability matrix (backend/auth/mobile on/off), a Definition of Done checklist derived from your success checks, and a phased development roadmap (M0→M3).

4

Preview the scaffold

See the file tree Sweep would generate: web/ for the static front-end, optional server/ if backend is needed, tests/, docs/, and configuration files. The structure reflects your capability matrix.

5

Save to catalog

Save the project to your workspace catalog. Export as JSON anytime. The demo project is always visible so the catalog is never empty.

6

Next steps (future)

In a future version, Sweep will integrate with the /sweep pipeline to actually generate the code, run verification, and sync to GitHub and Obsidian.

Core principles

  • Verification-first: Prove the app runs before saying "done"
  • Ownership: You own the code, tests, docs—no lock-in
  • Memory + catalog: A longitudinal system, not one-off chat→code
  • Static-first: GitHub Pages deployable, zero dependencies
