How to use Sweep

Sweep turns rough app ideas into checkable plans. Follow the flow: guided intake → brief → plan (Build/Grow/Earn) → verify → generate → sync.

1

Create or unlock your workspace

Choose a workspace name and a strong passphrase. Your data is encrypted at rest in your browser using WebCrypto (PBKDF2 → AES-GCM). No server, no network—everything stays local.

2

Use guided intake or write a brief

Type your idea in plain words. Sweep drafts the brief locally — no AI, no network. Or fill the brief fields manually: problem, target user, job-to-be-done, and 2–4 success checks.

3

Review the Build → Grow → Earn plan

Sweep produces a capability matrix, Definition of Done, phased roadmap (M0→M3), plus Grow (launch/reach) and Earn (offer/pricing) checklists. All generated locally from your brief.

4

Verify the implementation

Complete verification gates: smoke tests, visual checks at desktop + mobile sizes, acceptance criteria from your brief, repo checks (build/test scripts), and secret scanning. Mark as verified when all gates pass.

5

Generate scaffold files

Get ready-to-use file contents for your project: web/index.html, styles.css, app.js, optional server/server.py, tests, docs, README, .gitignore, and an Obsidian memory note. Copy or download individual files or the complete bundle.

6

Save to catalog

Save the project to your workspace catalog. Export as JSON anytime. The demo project is always visible so the catalog is never empty.

Core principles

  • Verification-first: Prove the app runs before saying "done"
  • Ownership: You own the code, tests, docs—no lock-in
  • Memory + catalog: A longitudinal system, not one-off chat→code
  • Static-first: GitHub Pages deployable, zero dependencies
