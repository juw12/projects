About

Send push notifications from your own server, and prove they work on a real phone. One self-hosted,
zero-dependency toolkit (Python standard library only), free. Status: work in progress.

Push Lab has two built-in parts that start together and are already linked:

Part Folder What it does
Beacon — the push server beacon/ Your own push service (like OneSignal). Web Push for every PWA, FCM for Android, in-app banners, ntfy / Bark (iPhone) / Gotify / Apprise channels, targeting, scheduling, digests, multi-step escalation, templates, per-user categories & preferences, Gatus uptime alerts, a console and MCP.
Tether — the device lab tether/ Your Android phone in the browser. Live HD screen, record and replay QA flows (Maestro / Midscene YAML), one flow on every connected phone at once, notification checks, AI steps (incl. Google ARTEMIS), performance budgets (startup, jank, memory, CPU), Perfetto traces, LeakCanary leak checks, CI and MCP.
Agent skills plugin/ Claude Code / Codex skills + CLI that drive both parts.

Start (2 minutes)

  1. Double-click start-push-lab.bat (or run python apps/pushlab/pushlab.py). The Beacon console and Tether open in your browser, already signed in.
  2. In Tether, click Install it for me if it asks for adb. That's a one-time ~7 MB download from Google.
  3. Connect a phone. Either plug it in with USB debugging on, or click 📶 Wi-Fi (Android 11+, no cable).
  4. In Tether, go to the Push tab and click 📲 Connect this phone to Beacon. Tether opens Beacon on the phone and taps Enable and Allow for you.
  5. Click Send now, or + full push QA steps, then Run.

There's no HTTPS or deployment needed for testing. Tether forwards your local Beacon to the phone as localhost (adb reverse), and browsers treat that as secure.

Ship it to real users

Deploy Beacon on HTTPS. It takes about 10 minutes with a Cloudflare Tunnel or Docker + Caddy: see beacon/docs/DEPLOY.md. Then add two lines to any of your apps (see the console's Setup tab). Keep Tether pointed at the deployed Beacon to test production pushes on your phone.

Built on open source

Project Used for
scrcpy (Apache-2.0) Tether HD: 30 fps H.264 + instant input
Maestro (Apache-2.0) Tether imports/exports Maestro YAML flows
cloudflared (Apache-2.0) Beacon "Go live": public HTTPS in one click
ntfy (Apache-2.0) Beacon channel: ntfy app topics
Apprise (BSD-2) Beacon channel: Telegram/Slack/Discord/email…
Bark (MIT) Beacon channel: native iPhone pushes (bark-server API v2)
Gotify (MIT) Beacon channel: self-hosted push server + Android app
Gatus (Apache-2.0) uptime checks → Beacon alerts via /v1/hooks/gatus
SoloPi (Apache-2.0) metric set for Tether's perf tools (startup, memory, jank, CPU)
Perfetto (Apache-2.0) Tether system traces (perf_trace_start/stop), opened in ui.perfetto.dev
LeakCanary (Apache-2.0) memory-leak results Tether reads from logcat (assert_no_leaks) — your debug build includes it
Midscene.js (MIT) Tether imports its YAML scripts (aiAct, aiTap, aiAssert, aiWaitFor …)
STF (Apache-2.0) / lamda the device-farm idea behind --all / /api/flow/run-all (one flow, every phone, in parallel)
Novu (MIT) the ideas behind Beacon's categories + preferences, templates and multi-step workflows (re-implemented, no Novu code)
android-emulator-runner (Apache-2.0) CI template
mobile-mcp (Apache-2.0) tool names/arguments Tether's MCP server is compatible with
Agent Skills format the plugin/ skills pack
Ollama (MIT) or any OpenAI-compatible server optional Tether AI steps
ARTEMIS (Apache-2.0) optional engine for Tether AI steps (Flash/Pro agents); its "explore, then write deterministic tests" mindset in the QA skill

All are optional downloads or optional pip installs — Beacon and Tether stay zero-dependency Python.
